## The five decisions in this phase that are decisions, not implementation

**A push is made idempotent by a table, and the reason is that two of its three payloads have no
natural key.** The turns were already safe — the engine allocates the seqs — and so are the latency
samples, on `(session_id, turn_seq)`. **`ai_call_log` has none.** So a retried push billed the same
model calls a second time, and every cost figure downstream would have become a number taken on
trust, which is precisely what `cache_write_units` exists as a separate column to prevent. That is the
whole of `voice_exchanges`: the agent's `exchange_id` is its primary key, inserting the row is the
claim, a unique-constraint collision is the `duplicate: true` the agent already expects, and the claim
is inside the same transaction as the write so two pushes racing under one id cannot both proceed.

**`usage_ledger` meters seconds, and spec §10 is amended to say so.** The spec had
`kind voice_minutes|avatar_minutes, quantity`, and minutes are wrong here for one concrete reason:
**a leg is not a session.** A candidate on a Nigerian mobile network reconnects, so one interview is
several legs; three legs of forty seconds is two minutes of voice, and rounding each leg up would
meter three — charging a candidate for reconnecting. Rounding happens once, where they are *shown*
their allowance. And the allowance is read as a `SUM` over an append-only ledger rather than kept as a
counter, because a counter has to be right on every path including the ones that fail half way.

**Voice is refused at session creation, not at the microphone.** A session pinned as `voice` that can
never be joined has spent that candidate's four questions on nothing — and those questions then count
as "seen" for the next twenty sessions (`withHistory`). So `CreateInterviewRequest` gained `mode`, and
the three refusals (`voice_not_enabled`, `voice_consent_required`, `voice_allowance_exhausted`) fire
before a single question is pinned. The token route asks the same question again, because an allowance
can run out between the two. The rule is one function in `VoiceEligibilityService`, which lives in its
own module precisely so that both sides can import it: `VoiceModule` depends on `InterviewsModule`
(voice is a transport over the engine, so it knows about interviews and an interview knows nothing
about rooms), and session creation would otherwise be a cycle.

**`@ServiceOnly()` is a second global guard, not `@Public()` with a check inside it.** `@Public()`
would have said in the metadata that an internal route is public, which is the opposite of true, and
default-deny would then have rested on a decorator somebody could forget. Instead the two guards
partition every route: `AuthGuard` needs a session unless the route is `@Public()` or `@ServiceOnly()`,
and `ServiceTokenGuard` needs the token **only** on `@ServiceOnly()`. A route carrying no marker at all
is still refused, by the other guard, exactly as before.

**The "analytics event" is a durable row and a log line, and that is deliberate.** The plan owed
`voice_fallback_to_text` (spec §9). There is **no emit path in this codebase at all** — PostHog is
initialised in the browser with `autocapture: false` and captures nothing, and M9 owns the typed event
helper and its no-PII test. Building half of that layer now would be the second implementation of
something M9 then has to design properly. So the fallback is a `voice_legs` row with
`reason = fallback_poor_connection`, counted on the admin latency view, and M9's event is derived from
it. Spec §9 now says this is the rule for every milestone before M9 that owes an event.

## Two bugs this phase found, one in its own code and one older

**The service-token guard accepted a bare token.** `header.replace(/^Bearer /i, "")` treats a raw
token as a well-formed header, so `authorization: <token>` was accepted. Harmless on its own — you
still need the token — and exactly the leniency that ends up being how a token arrives somewhere it
should not. The scheme is required now, and the test that found it also covers `Basic <token>` and a
token of the wrong **length**: `timingSafeEqual` throws on unequal buffers, which would have turned a
length mismatch into a 500 and leaked the token's length through the difference between two statuses.

**`consent-copy.ts` built a key union that could never be satisfied**, and it had been waiting for the
first version bump since M1. `consent.types.${type}.v${CONSENT_VERSIONS[type]}` over the whole
`ConsentType` union expands to every type at every version, so bumping `audio_processing` to v2 made
it demand `recording_storage.v2`, which no copy answers. A **mapped type** fixes it — inside one, `T`
is a single type and `CONSENT_VERSIONS[T]` is that type's own version — and the compile-time check the
file exists for is kept rather than cast away. `consents.service.spec.ts` had the same shape of
problem from the other side: a fixture that wrote `version: 1` for every type stopped being a fixture
the first time "current" moved.

**And the sixth `DROP INDEX questions_embedding_hnsw`**, in a migration that touches neither
`questions` nor a vector. Deleted, with the reason in the file. `migration-sql.spec.ts` would have
failed the build — which is why that test exists rather than eyes.

## The room, and what the leak test now asserts

ADR-0019 §4 says the answer key never enters the room. `content-no-answer-key.int.spec.ts` now holds
that as a test rather than a convention, through a recording stand-in (`FakeVoiceRoom`) that keeps
**every payload the API handed the media server** — so a metadata field added later is covered without
the test being touched. Four claims:

- the detector finds no answer-key marker and no probe in any of it;
- the dispatch has exactly the fields it has (`room`, `sessionId`), so a second one has to be argued
  for here;
- the room name and the participant identity are derived from the **session**, and the payloads
  contain neither the user's id, their email nor their name — a room name is visible to everyone in
  the room and appears in LiveKit's own dashboards, and a user id would link every room that candidate
  has ever been in;
- the join token's own claims carry no `name`, `metadata` or `attributes`, asserted by decoding the
  JWT rather than by the absence of three lines of code, and grant a microphone in one room with no
  data channel and no camera.

**The worker's channel is asserted from the other side**, because it legitimately carries part of the
key: the bundle route **must** contain the probes (a bundle that quietly stopped carrying them would
break follow-ups everywhere and fail nothing), and must still contain no rubric, criterion, descriptor
or ideal point. Two field **names** are allowed — `criterion_count` and a probe's `criterion` — because
both are numbers rather than prose, and a control proves that allowance is not a widening.

The internal routes are `@ApiExcludeController()`, which keeps them out of the browser's generated
client and therefore out of the prefix enumeration the coverage test uses. A test now asserts the
document publishes **no** `/api/internal` path, so removing that exclusion fails and has to be argued
for — which is the shape of an accidental hole the leak spec's own notes warn about.

## The decision taken after this phase: a resumed leg re-speaks the question

**Taken by the owner on 2026-09-30, recorded in ADR-0019 §7, and built at the start of phase 5.**

Phase 3 left a resumed leg silent — `resume` meant "they have already been greeted, so wait" — and
this handover raised the cost of that and left it to be decided with the captions in front of us. The
answer is **re-speak**: the interviewer says a short pinned line ("We lost the connection for a
moment. Here's the question again.") and then puts the last interviewer turn again, from the same
words and the same audio where there is any, while the captions still show it.

The owner's reason is the one that decides it: **reconnections will be common on Nigerian mobile
networks**, so this is the ordinary case rather than an edge, and a candidate should not have to answer
a question they did not hear. That is the same principle as M4's clock rule and phase 3's two barge-in
rules, reached from a third direction — a candidate never loses marks for something they did not hear,
and silence after a reconnection is exactly that with the connection to blame instead of them. Relying
on the captions asks somebody to read back through a transcript on a phone at the moment their
connection has just failed, and says nothing about *why* nothing is happening.

**What phase 5 owes.** `VoiceSessionStartResponse` gains the last interviewer turn, and the leg's side
of it is built first, before the screen. Three constraints come with it, all inherited from the repeat
rule this is a sibling of: **no model call**, so a re-spoken question cannot become a different one;
the pinned or prefetched audio where there is any; and it is **not a new turn** — nothing is pushed,
because the engine asked its question once and a reconnection is a transport event. The pinned line
joins `voice/acknowledgements.py` and is held to the same no-praise test as the engine's other words.

**And the analytics event stays as built**: the owner confirmed that the durable `voice_legs` row is
the right answer for now and that M9 derives `voice_fallback_to_text` from it.

## Carried into phase 5

- **Nothing has run end to end through a room.** The API's half is tested against the contracts and
  the agent's half against Protocols; the first real leg needs phase 5's browser. The int spec's
  pushes are hand-built, which proves the shapes the contracts describe and **not** that the agent
  builds them.
- **The `LiveKitRoom` dispatch rule has never met LiveKit.** `listDispatch` before `createDispatch` is
  asserted against a double; that a reload really produces one interviewer rather than two is phase
  5's browser and phase 8's staging deployment.
- **`/admin/voice` is captured empty** in the visual run, because `VOICE_ENABLED` is false there and no
  voice session can be started. Its empty state is the right thing to photograph at this phase; a
  voice e2e with a fake media device (phase 5) is what would let it be captured with a measurement in
  it, and phase 8 is when the measurement means anything.
- **Re-speaking on resume is the first thing phase 5 builds** (above): the contract change, the pinned
  line, and the leg reading it — before the screen, because the screen's captions are what it is
  decided against.
- **Two of the three items phase 3 carried are still phase 5's**: a dropped interjection that the
  captions show and no stored turn holds, and an unheard question past the repeat cap. The third, the
  silence on a resumed leg, is now decided.
