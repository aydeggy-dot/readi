## The three things that shaped it

**A person reading a transcript is its own processing purpose.** Spec §4.4 has committed the MVP to
expert blind-scoring since kickoff, and none of the four existing consent types covered it — so
`interview_intro.v1` had been telling candidates "nobody else is listening", v2 retired that as
untrue and deliberately said nothing, and its own header recorded that the silence had to be
re-read when this was taken. ADR-0017 is that reading: an opt-in, default-off, refusable consent,
one rule for "granted" in `isCurrentGrant`, and a **conditional** clause in `interview_intro.v3` so
the interview says aloud what the candidate agreed to and says nothing when they did not. No
reassurance either way — that was v1's mistake, and putting it back in a quieter voice would be the
same mistake.

**The rubric reaches a model for the first time, so the door is where the other doors are.**
`session-bundle.ts` now crosses four widths rather than three, and the evaluator's is the widest —
which is why it is the careful one. It carries the criteria with their descriptions and ladders, and
deliberately **not** the weights (the weighted roll-up is arithmetic and belongs in code; a model
told one criterion is 45% of the answer will skim the rest) and **not** the planned follow-ups (the
probes that were asked are already in the exchange; the unasked ones would have it scoring "did they
answer the probe"). The mirror image is narrowed rather than forbidden: `ideal_points` reach the
candidate as "what a strong answer covers", allowed only once the session has been scored — the same
shape M3 found for planned follow-ups.

**Evidence verification is a fairness feature before it is a security one.** Models tidy quotes, and
the more a candidate's phrasing differs from standard English the more there is to tidy — so a
strict matcher would drop the evidence of exactly the candidates this product exists to serve. That
is the failure mode, not a rounding error. The prompt is the first half of the defence (quote
verbatim, never correct spelling or grammar, never render Pidgin into standard English, a tidied
quote is discarded) and the matcher absorbs what is left: case, punctuation, curly quotes, a tidied
plural, a corrected typo, a dropped filler. What it does not absorb is translation, because that is
different words rather than different spelling — and once a paraphrase passes, a fabrication passes
too.

## The injection gate, and the line it cannot hold

This is the first call in the product whose output is a **mark**, so a successful injection takes
something real. Seven payloads are tested — plain, hidden in a code comment, a fake rubric update,
claiming to be the interviewer, claiming to be Readi staff, closing the data block, and asking for
the answer key — against three layers:

1. Each turn is wrapped by `as_data` **on its own**, so no answer can close its block and open one
   that looks like the interviewer. Asserted on closing tags, because the template's legend line
   names both openers by name and a legend is not a turn.
2. The rule is in the system prompt, asserted against the rendered text, so a rewording that drops
   the clause fails in CI rather than in production.
3. Fabricated evidence cannot be stored. This layer holds even if the model is wholly taken in: a
   model handing out 4s has to produce words the candidate really said.

**And the limit is a test rather than a silence.** If the model quotes the injection *itself*, the
quote is genuinely something the candidate typed, it verifies, and the inflated score stands.
`test_the_gate_does_not_catch_a_real_quote_used_to_justify_nonsense` records that on purpose, so
nobody reads the file as a claim that scoring cannot be gamed. What covers it is the prompt, the
agreement metric in `/evals`, and expert calibration — and if a future guard catches it, that test
fails and should be rewritten to describe the guard. **The owner has since decided what that guard
is** (`tasks/todo.md`, "Decided for phase 3"): flag the evaluation, do not change the score, and show
admins the flagged sessions.

## Three gates in front of a stored score

Each has a corrective message, so a retry is told what to fix rather than asked again in the same
words: every criterion exactly once; every quote the candidate's own; and **no level descriptor
echoed into prose the candidate reads**. The third was not in the plan and was added while writing
the prompt: `reasoning`, `strengths` and the tip all appear in the report, so a descriptor pasted
into one is the answer key leaking through the one surface `content-no-answer-key.int.spec.ts` can
never see — a model's own words.

A **0 with** a quote is deliberately allowed. A candidate can address a criterion squarely and be
wrong, and quoting the sentence where they were wrong is the fairest thing the report does; it is the
case the rubric descriptors were rewritten for in September 2026. A rule demanding empty evidence at
0 would push the evaluator into scoring 1 just to keep its quote.

## What was found on the way

**`ConsentType` is a Prisma enum**, so adding a consent type is three changes and not one: the
constant, the enum with its own migration, and the copy block. The plan had not accounted for the
column. It also sends every existing account back to the consent screen, which is the intended
behaviour and cost nothing today.

**`docs/privacy/subprocessors.md` had been wrong for a milestone.** The Anthropic row described CV
parsing and nothing else; candidate answers have gone there since M3, and M4 adds the rubric and the
per-question transcript. Corrected, with the reviewers recorded as contracted **processors** and
`docs/privacy/reviewer-agreement.md` written as a draft that says on its own face it must not be
signed until a lawyer familiar with the NDPA 2023 has read it.

**The seventh and eighth `DROP INDEX questions_embedding_hnsw`.** One in a migration that adds a
single enum value, one in a migration that only creates tables. Both deleted;
`migration-sql.spec.ts` would have failed the build otherwise.

**`pnpm gen:contracts` and `pnpm typecheck` were building the web app**, which CLAUDE.md forbids
beside a running dev stack and does not warn about. `turbo run typecheck --dry=json` said it in one
line — `@readi/web#gen:contracts <- @readi/web#build` — because turbo synthesises a node for a
configured task in every package, including packages with no such script. The dependency moved into
`packages/shared-types/turbo.json`, where it is genuinely needed, and `gen-api-client.sh` switched to
`build:standalone` so the API writes `dist-cli` rather than the `dist` that `nest start --watch`
owns. Both commands are now safe beside a running stack. **This was found by running one of them
against the owner's live servers first**, which is the lesson.

**`model_copy(update=...)` skips validation.** Marking an `AiCallRecord` as rejected left a bare
`str` in a field the generated model types as a root model. It serialised to the right characters by
luck and made Pydantic warn; now it is rebuilt through validation and the warning is a failing test.

**CLAUDE.md asked for something the models reject.** "Evaluation runs … with low temperature":
current Claude models take no sampling parameters, which `llm/anthropic_client.py` already knew and
said in a comment. A `TEMPERATURE` constant and a test asserting it were written before that was
noticed, and both are gone. What actually holds a score steady — the constrained schema, `effort:
low`, a fixed 0–4 ladder — is written where the constant would have been, with the note that
stability is something `/evals` measures rather than something we assume.

## Verifications

- **The bundle's consent flag, watched failing.** Hardcoding `false` in `bundleFor` fails the new
  integration test and nothing else in the suite notices.
- **The evaluator's width, watched failing.** Spreading the snapshot's criteria into the evaluation
  request fails the "no weight" assertion — which is the point of the test, because a spread defeats
  TypeScript's excess-property check and the type alone would not have caught it.
- **Erasure, guarded at the schema.** A new test walks *every* foreign-key path from
  `answer_evaluations`, `session_reports` and `calibration_scores` to `users` and fails on any hop
  that is not `CASCADE`. It is shown a planted counter-example first, because every real path in this
  schema cascades and a walker that found nothing would have passed just as quietly.
- **The evidence rule now has both readers it was written for.** `evidence-cases.json` is run by
  `evaluations.test.ts` and by `test_evaluation_evidence.py`, which is what ADR-0003 decision 5 asks
  for and what `ask-vectors.json` set the precedent for.

## What is not done, and is not hidden

- **Nothing calls the evaluator yet.** There is no job, no scoring rule, no report and no route; the
  worker endpoint exists and is tested against a scripted model and against the stand-in. Phase 3.
- **The prompting adjustment is a decision, not code.** 0.85 on any non-zero score, keyed on the
  engine fact rather than the coverage model's verdict, under `SCORING_VERSION`. Phase 3, and it must
  handle a criterion carrying two probes — `review-doc.ts` keyed a map by criterion and silently
  dropped the second.
- **The leak test has not been widened**, because there is no report route for `idealPointMarkers` to
  be asserted against. The shape decision is already enforced in the contract, with a test.
- **The evaluator has never run against a real model.** Every number in `.env.example` about what it
  costs is an estimate from M3's measured token counts. Phase 7 makes the paid run, and the owner has
  asked for a sonnet-5 vs opus-5 agreement comparison with a recommendation.
- **Phase 6 is gated.** No real reviewer is given access until a lawyer-reviewed, signed
  `reviewer-agreement.md` exists; the calibration tool is built and demonstrated against
  staff-authored answers until then.
